# MCP 服务 mcp_service

## 边界

- 负责：将登记、知识读写和检索结果适配为外部编程客户端可理解、可据以行动的工具返回。
- 不负责：项目登记存储、知识持久化与同步任务、Git 工作流队列、Git 对象读取和版本计算、内存索引生命周期。

## 关键概念

- 登记：当前服务存在仓库登记记录，不表示检索已就绪。
- 已受理：服务有明确依据承接文件版本的知识处理，不表示提交文字已覆盖既有知识或立即可检索。
- 未覆盖：该文件版本已有完整可读知识，提交文字未替换既有内容。

## 需求约束

- MCP_SERVICE-01 MCP 返回必须准确表达操作能够证明的结果；不得以无活跃内存实例证明未索引，或以活跃实例证明可检索。
- MCP_SERVICE-02 MCP 返回必须保留客户端能据以纠正的参数、路径、文件版本及内容超限信息；不得将真实读取失败表述为没有知识。
- MCP_SERVICE-03 文件知识提交仅限存在明确的处理承接依据时确认已受理；已有版本未覆盖提交文字时必须准确说明。
- MCP_SERVICE-04 注册表保存失败必须进入注册失败响应；注册失败响应不得宣称已完整回滚。
- MCP_SERVICE-05 MCP 展示不得额外触发索引加载、修改搜索排序或改变注册授权边界。
- MCP_SERVICE-06 MCP 返回可保留正常报告、知识说明正文、实际返回数量及用于核对对象的标识和版本；不得机械删除所有数字。
