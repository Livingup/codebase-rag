# 工作流编排 workflow · 技术设计

## 内存视图构建

- 不变量：构建新内存实例必须走临时 staging 实例，持久化知识加载成功后才原子提升为活跃实例；失败只销毁 staging，不得在活跃实例上原地重建。
- 方案：初始化分全量与增量两档：全量为缺失的合格文件生成知识后整体装载；增量只装载已持久化的版本，不为缺失文件触发生成。

## 提交同步

- 不变量：纯重命名（blob 不变）必须复用原知识点的描述与向量，仅更新路径与版本元数据，不得重新生成。
- 方案：灰区文件分类先查持久化类型键缓存，未命中才走 LLM；LLM 仍无法判定的类型按排除处理。

## 失败补偿

- 方案：补偿循环先重试 knowledge_sync 外发箱，再处理失败文件；超过最大重试或源 blob 已不存在的失败归档为死信；重试不同时做内存更新。
