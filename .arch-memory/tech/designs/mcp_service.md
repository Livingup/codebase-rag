# MCP 服务 mcp_service · 技术设计

## 仓库登记与查询

- 方案：登记列表和单仓查询使用登记关系；仅将正在执行的初始化识别为初始化进行中，不新增等待队列展示或检索可用性探测（依据 MCP_SERVICE-01、MCP_SERVICE-05）。
- 方案：注册主链采用严格保存，维护性保存保留尽力保存策略；共享的 REST 注册沿用既有失败映射，不因 MCP 展示变化修改 REST 展示模型（依据 MCP_SERVICE-04）。
- 方案：注册跨越登记、监控和任务安排的部分副作用不采用全链事务回滚。

## 文件知识提交

- 方案：受理依据采用即时持久写入确认，或完整可恢复待办与当时可运行的自动补偿；不新增后台任务或存储系统（依据 MCP_SERVICE-03）。
- 方案：受理责任以正常文件系统及服务运行条件为边界，不采用断电零丢失、确定处理期限或永久最终交付保证；后续版本替代与跨文件非事务语义保留。
- 不变量：附带内存更新或任务清理失败不得反转已证实的持久写入或任务承接结果。
- 方案：文件知识提交的真实文件处理失败使用 MCP 工具错误表达；其他工具的错误协议独立维护，不随展示调整统一重构。

## 已提交文件知识读取

- 方案：严格区分 Git 读取错误与正常无文件仅用于文件知识读取入口；其他 Git 读取调用保留兼容行为（依据 MCP_SERVICE-02）。

## 检索与源码分析

- 方案：相关性排序保留，搜索响应不展示混合来源评分；正常源码分析报告保留原文，不以固定文件计数声明分析完成度（依据 MCP_SERVICE-01、MCP_SERVICE-05、MCP_SERVICE-06）。
